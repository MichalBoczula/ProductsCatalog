# Generated source documentation (REF-10/1)

ProductsCatalog and ECommerceStoreUsers generate their documentation from
executable sources. REF-10 links those sources and fills missing descriptions
in code. No handwritten per-operation JSON, parallel OpenAPI file or checked-in
response snapshot is the source of truth.

## Inputs and ownership

| Information | Authoritative source | Generated output |
| --- | --- | --- |
| HTTP method/path, public DTOs, response status and media type, `operationId` | Minimal API registration, DTOs and `.Produces` metadata | OpenAPI generated by the service |
| Ordered steps, decisions and side effects | Application flow descriptors and the application behavior they describe | Products `/products-documentation/flow`; Users `/users-documentation/flows` |
| Domain validation rules and possible errors | Domain validation policies and rule descriptors | Products `/products-documentation/validation-policies`; Users `/users-documentation/validations` |
| Observed status and distinct cause | Reqnroll scenarios with HTTP and durable-state assertions | `docs/acceptance-matrix.tsv` links cases to operations and scenarios |

The current documentation endpoints have different response shapes. Keep
their routes and existing response contracts until a separately reviewed
compatibility change; a build-time projection can normalize them without
changing callers. Generated OpenAPI remains the authority for HTTP schemas.

## Join rules for a generated view

- Identify an operation by `(service, operationId)`, where `service` is
  `products` or `users` and `operationId` matches the case-sensitive endpoint
  `.WithName(...)`. Match method and route template against generated OpenAPI.
  The existing `GetFiltered MobilePhones` name includes a space; any rename
  needs a coordinated update of endpoint, OpenAPI, matrix and references.
- Assign stable `flowId` and `policyId` in descriptor/policy source metadata
  when the generated view needs them. Scope these IDs by service and keep them
  independent of display names, method order and routes. A flow belongs to an
  operation; a policy may be linked to several operations. Keep existing
  descriptor payloads compatible until an API change is explicitly reviewed.
- Assign stable step/rule IDs in their source metadata when linking individual
  steps or rules. A wording or ordering change must not silently change an ID.
  Do not guess links from C# class names or prose.
- Read `scenarioId` verbatim from the existing matrix. Each distinct
  `(operationId, status, cause)` needs a row linked to a real scenario that
  asserts that outcome. A `200` empty list and `200` populated list, or two
  different `404` causes, remain distinct. A missing scenario is a reported
  coverage gap, not a synthesized success.
- Describe no-op, conflict, not-found, rollback, current/history effects and
  failure branches in the owning code and tests. If a descriptor cannot
  express a behavior, extend that descriptor in the appropriate follow-up PR
  and compare it with the runtime behavior. Never infer business behavior
  solely from a response status or an exception string.

The eventual generated view may carry a version for its *output shape*. That
version is distinct from Mongo document versions, SQL migrations and API
versioning. Set it when a generator and consumers exist; do not add a
`schemaVersion` field to production documents or HTTP contracts for this task.

## Checks and scope

The service already checks acceptance matrix IDs, endpoint registrations,
declared statuses and scenario references with
`python3 scripts/check-acceptance-matrix.py`. REF-10/2–5 will improve actual
flow and policy source metadata and test semantic links. REF-10/6 can generate
the normalized view, fail on orphaned or duplicate IDs, and compare generated
references across both repositories. REF-11 will verify runtime/OpenAPI drift.
Generated artifacts should be produced by CI or a local command and need not
be committed. This task makes no runtime, database, route, package, Allure
publication or RAG ingestion change. Generated documentation must exclude
secrets, personal data and raw exception messages.
